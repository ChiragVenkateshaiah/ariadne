# Ariadne intelligence plane

## Package layout gotcha (read before adding new modules)

Two source trees share the top-level Python package name `ariadne`, merged at
import time as a single **PEP 420 namespace package**:

```
brain/ariadne/graph/...     <- hand-written (this is our code)
brain/pb/ariadne/v1/...     <- generated by `buf generate` (DO NOT EDIT)
```

This works because **neither `brain/ariadne/` nor `brain/pb/ariadne/` has an
`__init__.py`** at that top segment, and the venv has both `brain/` and
`brain/pb/` on `sys.path` via `.venv/lib/python3.10/site-packages/ariadne-dev.pth`.

Why it's split this way: protoc-gen-python derives `ariadne.v1.xxx_pb2` from
the *file path* of the `.proto` sources (`proto/ariadne/v1/xxx.proto`), not
from anything in `buf.gen.yaml`. That import path is fixed. Our own code is
also logically `ariadne.*`. Making the top segment an implicit namespace
package is the standard way to let both live under one name without one
`__init__.py` shadowing the other and breaking the merge.

**Rules that keep this working:**
- Never add `brain/ariadne/__init__.py`. If some tool re-creates it, delete it.
- Never hand-edit anything under `brain/pb/` — it is fully regenerated by
  `buf generate` from the repo root.
- If the venv is recreated, re-add the `.pth` file:
  ```
  printf '%s\n%s\n' "$(pwd)/brain" "$(pwd)/brain/pb" \
    > brain/.venv/lib/python3.10/site-packages/ariadne-dev.pth
  ```
- Subpackages that exist in only one tree (`ariadne.graph`, `ariadne.v1`) are
  free to have their own normal `__init__.py` — the constraint is only on the
  shared top segment.

## Setup

```
cd brain
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
printf '%s\n%s\n' "$(cd .. && pwd)/brain" "$(cd .. && pwd)/brain/pb" \
  > .venv/lib/python3.10/site-packages/ariadne-dev.pth
```

Regenerate protobuf code after any `.proto` change (from repo root):

```
buf generate
```
